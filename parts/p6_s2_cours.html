Chapitre 3 (partie 2) — Algorithmes de résolution

Objectifs : comprendre la différence entre algorithmes exhaustifs et gloutons ; s'initier à la notion et au choix d'heuristiques ; s'intéresser à la complexité ; connaître les principaux algorithmes de coloration propre.

I. Propriétés et comportements des algorithmes

Algorithme exhaustif (brute force)Algorithme glouton

Heuristique

DéfinitionUne heuristique est une règle de choix fondée sur une intuition ou sur une propriété du problème, utilisée pour chercher rapidement une bonne solution, sans garantir qu'elle soit optimale. Elle ne change pas l'objectif de l'algorithme : elle guide ses choix pour augmenter les chances d'obtenir une bonne solution. (Du grec heuriskô : « je trouve ».)

Complexité temporelle

L'efficacité d'un algorithme se mesure par la mémoire utilisée et la rapidité d'exécution, c'est-à-dire le nombre d'opérations en fonction de la taille n des données : c'est la complexité temporelle, notée O(f(n)) (ordre de grandeur de l'augmentation du temps quand n augmente). Familles : linéaire O(n), logarithmique O(ln n), polynomiale O(nᵏ), exponentielle O(kⁿ).

Problèmes faciles et difficiles
  • Un algorithme est « raisonnable » si sa complexité est polynomiale (O(nᵏ)).
  • Un problème est « facile » s'il admet un algorithme déterministe raisonnable.
  • Un problème est « probablement difficile » si personne ne sait prouver qu'il est facile et que la communauté scientifique soupçonne fortement qu'il est difficile : il est peu probable qu'on trouve un jour un algorithme polynomial pour le résoudre.

II. Trouver une coloration propre

Rechercher une coloration propre optimale est un problème algorithmique difficile. Une approche exhaustive teste toutes les combinaisons : c'est un algorithme brute force de complexité exponentielle. On utilise donc des algorithmes raisonnables qui ne garantissent pas l'optimum, mais qui, avec des heuristiques bien choisies, donnent en général un résultat satisfaisant en temps raisonnable.

1. Algorithme séquentiel « naïf »

PrincipeParcourir les sommets les uns après les autres et attribuer à chacun la plus petite couleur non déjà utilisée par un de ses voisins. Il est glouton : il ne remet jamais en cause les choix précédents.
Pour chaque sommet i :
    c ← 0
    Faire :
        test ← vrai
        Pour chaque sommet j déjà coloré (j < i) :
            si j est adjacent à i et que la couleur de j est c : test ← faux
        si (test = faux) c ← c + 1
    Tant que (test = faux)
    Attribuer la couleur c à i
LimiteIl dépend « du hasard » de l'ordre initial des sommets : deux ordres différents peuvent donner des nombres de couleurs différents. Sur l'activité 4, dans l'ordre du fichier (Anglais, Chimie, Chinois…), il utilise 5 créneaux alors que χ = 4.

2. Utiliser une heuristique

L'ordre de traitement a un impact sur le résultat. Quel ordre choisir pour avoir une meilleure chance d'utiliser peu de couleurs ? Commencer par les sommets qui semblent les plus difficiles à colorer. Mais comment les identifier ?

Idée 1 — séquentiel ordonné : degrés décroissants

Intuition : les sommets qui ont beaucoup de voisins sont les plus difficiles à colorer. Il n'existe pas de démonstration que cela donne une meilleure coloration, mais on observe que l'on obtient souvent moins de couleurs.

Tant que tous les sommets ne sont pas colorés :
    Chercher le sommet i non coloré de plus haut degré
    c ← 0
    Faire :
        test ← vrai
        Pour chaque sommet j déjà coloré :
            si j est adjacent à i et que la couleur de j est c : test ← faux
        si (test = faux) c ← c + 1
    Tant que (test = faux)
    Attribuer la couleur c à i

Idée 2 — Welsh et Powell : remplir une couleur au maximum

Welsh et Powell cherchaient à planifier des examens sans conflit. Leur algorithme a une stratégie centrée sur les couleurs : heuristique de « remplissage maximal ». En maximisant la taille de chaque classe de couleur, on « vide » le graphe de ses sommets les plus faciles à grouper, ce qui retarde au maximum l'apparition de nouvelles couleurs.

Trier les sommets par ordre de degrés décroissants.
c ← 0
Tant que tous les sommets ne sont pas colorés :
    Pour chaque sommet i non coloré (dans l'ordre) :
        test ← vrai
        Pour chaque sommet j déjà coloré :
            si j est adjacent à i et que la couleur de j est c : test ← faux
        si (test = vrai) : attribuer la couleur c à i
    c ← c + 1

Version Java (testée) :

static int[] welshPowell(boolean[][] adj) {
    int n = adj.length;
    int[] deg = new int[n];
    for (int i = 0; i < n; i++) for (int j = 0; j < n; j++) if (adj[i][j]) deg[i]++;
    Integer[] ordre = new Integer[n];
    for (int i = 0; i < n; i++) ordre[i] = i;
    Arrays.sort(ordre, (a, b) -> deg[b] - deg[a]);            // tri stable par degré décroissant
    int[] couleur = new int[n];
    Arrays.fill(couleur, -1);
    int restants = n, c = 0;
    while (restants > 0) {
        for (int i : ordre) {
            if (couleur[i] != -1) continue;
            boolean ok = true;
            for (int j = 0; j < n; j++) if (adj[i][j] && couleur[j] == c) { ok = false; break; }
            if (ok) { couleur[i] = c; restants--; }
        }
        c++;                                                    // on passe à la couleur suivante
    }
    return couleur;
}
Exemple (activité 4)Ordre : Ch(7), Cn, E, M, S (5), I, Me (4), A (3), P (2). Couleur 1 : Ch puis Cn (seul non voisin de Ch). Couleur 2 : E, puis I. Couleur 3 : M, A, P. Couleur 4 : S, Me. Total : 4 créneaux.
Différence avec le séquentiel ordonnéLe séquentiel ordonné traite un sommet à la fois et lui cherche une couleur ; Welsh-Powell traite une couleur à la fois et cherche à l'utiliser pour un maximum de sommets. Les deux utilisent l'ordre des degrés décroissants et peuvent donner des résultats différents.

Idée 3 — DSATUR : choisir dynamiquement le prochain sommet

Limite du tri par degré : il est statique (fait une fois avant de colorer). Or, dès qu'on colore, la situation change : un sommet de grand degré peut devenir très facile à colorer si tous ses voisins ont déjà la même couleur.

Définition (Daniel Brélaz)Le degré de saturation (DSAT) d'un sommet est le nombre de couleurs différentes déjà utilisées par ses voisins.
Tant que tous les sommets ne sont pas colorés :
    Chercher le sommet non coloré de degré de saturation maximal
        (en cas d'égalité : celui de plus haut degré)
    Lui affecter la plus petite couleur possible
AttentionOn compte les couleurs différentes, pas les voisins colorés : un sommet avec 3 voisins colorés tous de la même couleur a une saturation de 1, pas de 3.

Déroulé sur l'activité 4 (voir le détail dans les corrigés) : Ch (saturation 0, degré 7) → E → M → S → Cn → A → Me → I → P.

III. k-colorable ? nombre chromatique ? coloration optimale ?

  • Déterminer si un graphe est k-colorable, trouver le nombre chromatique et chercher une coloration optimale sont des problèmes difficiles : aucun algorithme polynomial n'est connu à ce jour. Des méthodes exactes plus élaborées que le brute force réduisent beaucoup la recherche, mais le problème reste difficile dans le cas général.
  • En revanche, on peut encadrer χ(G) : ω(G) ≤ χ(G) ≤ 1 + Δ(G), où Δ(G) est le plus grand degré et ω(G) l'ordre de la plus grande clique (sous-graphe complet).
  • On sait trouver des colorations optimales pour certaines classes particulières de graphes (graphes parfaits…).
ExempleActivité 4 : ω = 4 (clique {Cn, E, M, S}) et Δ = 7 (Chimie), donc 4 ≤ χ ≤ 8 ; on a trouvé χ = 4.

Explorer un graphe

RemarqueCette partie est rédigée à partir de l'activité 6 (exploration d'un wiki) : le chapitre de cours correspondant n'est pas encore dans les supports. Elle introduit les idées de base du parcours d'un graphe.

I. Le problème

Objectif : visiter toutes les pages accessibles depuis une page de départ, sans visiter inutilement la même page plusieurs fois et sans en oublier. Un wiki peut avoir des milliers de pages : il faut raisonner comme un ordinateur, sans dessiner le graphe. Quand on consulte une page, on n'a accès qu'à la liste de ses liens ; il faut donc mémoriser d'autres informations au fil de l'exploration.

Modélisation : sommets = pages ; arc p → q ⇔ la page p contient un lien hypertexte vers q (relation non symétrique : graphe orienté). Les doublons ayant été supprimés, c'est un graphe orienté simple (sans arcs multiples), représenté naturellement par des listes de successeurs.

II. Trois états pour une page

  • Non vue : on ne connaît pas encore son existence (aucun lien rencontré vers elle).
  • Vue mais non explorée : on l'a rencontrée dans la liste de liens d'une page explorée ; on devra l'explorer plus tard.
  • Explorée : on a consulté la liste de ses liens (tous ses successeurs ont été vus).

Pour ne pas tourner en rond, on ne rajoute à la liste des pages à explorer qu'une page pas encore vue (on la marque « vue » dès qu'on l'ajoute). Pour ne pas oublier de page, on continue tant que la liste des pages vues non explorées n'est pas vide.

III. L'algorithme

Choisir le sommet initial s0
Marquer s0 « vu » ; ajouter s0 à la liste AExplorer
Tant que AExplorer n'est pas vide :
    s ← retirer un sommet de AExplorer
    Noter que s a été exploré
    Pour chaque successeur t de s :
        si t n'est pas déjà vu :
            marquer t « vu »
            ajouter t à AExplorer

La seule liberté est quel sommet retirer de AExplorer :

Pile (LIFO)le sommet vu le plus récemmenten profondeur : on s'enfonce dans un chemin avant de revenir en arrière

IV. Structures de données

  • Pages vues non explorées : une file (Queue, ArrayDeque) pour la largeur, une pile (Deque utilisée en pile) pour la profondeur — pas une simple liste dans laquelle on chercherait à chaque fois.
  • Page déjà vue ? un boolean[] indexé par le numéro de la page, un Set (HashSet) de pages vues, ou un attribut d'état dans l'objet Sommet (non vu, vu, exploré). Un HashSet évite les doublons tout seul : vus.add(t) renvoie false si t y était déjà.
  • Graphe : listes de successeurs (Map<Page, List<Page>>), puisqu'on parcourt les successeurs d'un sommet.
static List<String> largeur(Map<String, List<String>> succ, String s0) {
    List<String> explores = new ArrayList<>();
    Set<String> vus = new HashSet<>();
    Deque<String> aExplorer = new ArrayDeque<>();
    vus.add(s0);
    aExplorer.addLast(s0);
    while (!aExplorer.isEmpty()) {
        String s = aExplorer.pollFirst();                    // file : le plus ancien d'abord
        explores.add(s);
        for (String t : succ.getOrDefault(s, List.of())) {
            if (vus.add(t)) aExplorer.addLast(t);            // add renvoie false si t déjà vu : pas de doublon
        }
    }
    return explores;
}

Pour le parcours en profondeur, la seule ligne qui change est aExplorer.pollLast() (on retire le dernier ajouté : pile).

ComplexitéChaque sommet est exploré une fois et chaque arc examiné une fois : O(n + m) avec des listes de successeurs, O(n²) avec une matrice d'adjacence (il faut parcourir une ligne entière pour trouver les successeurs).
À retenirExplorer un graphe, c'est maintenir trois ensembles : pages non vues, vues non explorées, explorées. On ne découvre que les sommets accessibles depuis le départ. Le choix « file ou pile » détermine l'ordre de parcours.
