Activité 2, sujet A — Modéliser un réseau social Chap. 2
1Identifier les données et construire le graphe
Entités : Compte (pseudo, photo optionnelle, bio optionnelle) ; Publication (date, contenu), appartenant à un compte.
Relation : « est abonné à » entre deux comptes, non symétrique.
Graphe : sommets = comptes ; arc U1 → U2 ⇔ U1 est abonné à U2. Graphe orienté simple : pas de boucle (on ne s'abonne pas à soi-même), un seul abonnement possible entre deux comptes dans un sens donné. Les publications sont des attributs du compte (grille) et non des sommets : le modèle ne cherche qu'à décrire qui voit qui.
2Graphe exemple
3Que peut-on déduire d'un tel graphe ?
  • Abonnés d'un compte = prédécesseurs = degré entrant ; abonnements = successeurs = degré sortant.
  • Qui peut voir quoi : les publications de U2 sont visibles par Pred(U2) (ses abonnés).
  • Les comptes les plus influents (fort degré entrant), les abonnements mutuels (arcs dans les deux sens), les comptes isolés, les communautés (composantes), les chemins (« amis d'amis » : suggestions d'abonnement), la façon dont une publication se propage.
4Pourquoi 100 abonnés affichés, mais 98 dans la liste ?
Le compteur est une valeur stockée à part (dénormalisée, mise en cache) mise à jour de façon asynchrone, alors que la liste est recalculée à l'affichage et exclut certains comptes : comptes supprimés, désactivés, suspendus ou bannis, bloqués, bots purgés. Le compteur est simplement « en retard » (cohérence éventuelle) : le modèle conceptuel est juste, c'est l'implémentation qui introduit un écart.
5Où stocker le nombre de publications de U2 likées par U1 ?
Cette donnée dépend du couple (U1, U2) : ni dans le compte U1 seul (il faudrait un tableau par compte suivi), ni dans U2 seul. Elle se stocke sur le lien d'abonnement U1 → U2 : attribut nbPublicationsLikees de l'arc. C'est un graphe valué.
6Diagramme de classes
  • Compte : pseudo (identifiant), photo et bio optionnelles (cardinalité 0..1).
  • Publication liée à Compte par une composition (1—*) : une publication n'existe pas sans son compte et disparaît avec lui.
  • Abonnement : le lien devient une classe (équivalent à une classe d'association sur la relation réflexive Compte *—* Compte), car il porte une information propre (nbPublicationsLikees) ; ses deux extrémités ont des rôles distincts (abonné, suivi). Règle : U1 voit les publications de U2 s'il existe un Abonnement U1 → U2.
7Pour aller plus loin
Likes, commentaires et partages comme classes ; comptes privés/publics et demandes d'abonnement ; blocages ; messages ; recommandation d'amis (voisins de voisins) ; détection de communautés ; pondération par la fréquence d'interaction ; notifications.
Activité 2, sujet B — Modéliser un réseau ferré Chap. 2
1Identifier les données et construire le graphe
Entités : Station (nom), Ligne (numéro, couleur) avec deux terminus. Relation : deux stations qui se suivent sur une ligne. Graphe : sommets = stations (une station sur plusieurs lignes est un seul sommet : c'est la correspondance) ; arêtes = tronçons entre stations consécutives, étiquetées par la ligne. Non orienté (on circule dans les deux sens).
2Graphe exemple
3Quels itinéraires calcule-t-on ?
Sans temps : existence d'un trajet entre deux stations (connexité), trajet le plus court en nombre de stations (parcours en largeur), nombre minimal de changements de ligne (en comptant les changements d'étiquette de ligne le long du trajet).
4Où stocker les temps de trajet ?
Sur les arêtes (attribut temps du tronçon), pas sur les sommets : un temps est une information sur le déplacement entre deux stations.
5Peut-on trouver les itinéraires les plus courts en temps ?
Oui : le graphe devient pondéré (temps positifs) et on cherche le chemin de poids minimal (algorithme de Dijkstra, vu plus tard). Limites : le temps de changement de ligne et l'attente ne sont pas modélisés.
6Diagramme de classes
  • Station et Ligne ont chacune un identifiant ; la ligne a deux terminus (association vers Station, cardinalité 2).
  • Liaison est un objet à part entière (origine, destination, ligne, temps) plutôt qu'un simple couple de stations : elle porte l'information.
7Raspail — Denfert-Rochereau sur les lignes 4 et 6
Un graphe simple impose une seule arête par paire de stations : on ne peut pas distinguer les deux lignes (ni leurs temps éventuellement différents). Il faut un multigraphe : une arête par (ligne, tronçon). Avec le diagramme ci-dessus, c'est déjà possible puisque Liaison est une classe indépendante de la paire de stations (deux instances Liaison avec des lignes différentes). Variante : un sommet par couple (station, ligne) et des arêtes de correspondance pondérées par le temps de changement.
8Pour aller plus loin
Temps de correspondance, horaires et fréquences (graphe dépendant du temps), lignes à fourches (RER), sens uniques, affluence, pannes, zones tarifaires, accessibilité, critères multiples (temps, changements, marche).
Exercice 1 — Matrice d'adjacence Chap. 2

Graphe orienté de l'énoncé, lu sur la figure : arcs A→B, B→A, C→B, B→D, B→E, B→F, C→F, F→C, F→D (9 arcs).

1Matrice d'adjacence (A, B, C, D, E, F = sommets 0 à 5)
{{MAT:ex1}}La case (i,j) vaut 1 si j est un successeur de i. Code d'initialisation : for (int[] a : arcs) g.ajouterArc(a[0], a[1]);
2Nombre de successeurs ou de prédécesseurs ?
Successeurs de i = somme de la ligne i (ex. B : 1+0+0+1+1+1 = 4). Prédécesseurs de j = somme de la colonne j (ex. D : B et F, soit 2). Vérifié en Java : nbSuccesseurs(1) = 4, nbPredecesseurs(3) = 2.
3Propriété pour un graphe non orienté ?
La matrice est symétrique (mij = mji), avec une diagonale nulle si le graphe est simple. On pourrait donc ne stocker que la moitié.
4Efficace pour savoir si deux sommets sont adjacents ?
Oui : accès direct en O(1) à matAdj[i][j].
5Graphes pondérés ?
On remplace le 1 par le poids (double[][]). Il faut une valeur « pas de lien » qui ne soit pas un poids possible : 0 si les poids sont non nuls, sinon +∞ (Double.POSITIVE_INFINITY), NaN ou null (Double[][]).
6Mémoire pour un graphe peu dense ?
Mauvaise : la matrice a n² cases quel que soit le nombre de liens m. Pour n = 10 000 sommets et 30 000 liens, 100 millions de cases dont l'immense majorité vaut 0.
7Du point de vue conception objet ?
Peu satisfaisante : les liens ne sont pas des objets (impossible de leur donner des informations, un comportement…) ; Sommet et la matrice sont deux structures séparées à synchroniser à la main ; la logique d'accès par indices (i, j) est de bas niveau.
8Difficultés liées à la numérotation ?
Il faut maintenir la correspondance identifiant ↔ numéro (Sommet.num) ; ajouter un sommet oblige à créer une nouvelle matrice (n+1)×(n+1) et à tout recopier ; supprimer un sommet laisse un trou ou oblige à renuméroter les suivants et à décaler lignes et colonnes ; le numéro stocké dans le Sommet peut devenir incohérent avec sa position réelle.
Exercice 2 — Liste d'arêtes Chap. 2
1Deux sommets donnés sont-ils adjacents ?
On parcourt toutes les arêtes en cherchant une arête dont les extrémités sont ces deux sommets : O(m).
boolean adjacents(Sommet a, Sommet b) {
    for (Arete e : aretes) if (e.relie(a, b)) return true;
    return false;
}
2Voisins d'un sommet ?
Parcourir toutes les arêtes et retenir « l'autre extrémité » de celles qui touchent le sommet : O(m) également, même si le sommet a peu de voisins.
3Adapter aux graphes orientés ?
Les deux extrémités de l'arête deviennent ordonnées : origine et destination (au lieu de deux extrémités équivalentes). relie(a,b) ne teste plus que le sens a → b.
4Adaptée aux multigraphes ?
Oui, très naturellement : chaque lien est un objet Arete avec son identifiant et son information ; rien n'empêche d'avoir plusieurs arêtes entre les mêmes sommets (exemple Raspail–Denfert).
5Cohérence à la suppression d'un sommet ?
Il faut supprimer aussi toutes les arêtes incidentes à ce sommet, sinon elles référencent un sommet qui n'existe plus : aretes.removeIf(e -> e.touche(s)); sommets.remove(s); (vérifié : après suppression de B dans A–B–C, il reste 2 sommets et 0 arête).
Exercice 3 — Liste de successeurs Chap. 2
1Nombre de successeurs ?
Taille de la liste : successeurs.size(), en O(1). (Dans un multigraphe avec doublons, cela donne le nombre d'arcs sortants, pas de successeurs distincts.)
2Prédécesseurs ? Comment l'accélérer ?
Sans structure supplémentaire, il faut parcourir la liste de successeurs de tous les sommets (O(n + m)). Pour accélérer : chaque sommet mémorise aussi une liste de prédécesseurs.
  • Avantage : accès direct aux prédécesseurs.
  • Inconvénients : mémoire doublée, et à chaque ajout ou suppression d'arc il faut mettre à jour les deux listes (risque d'incohérence). Dans le code : ajouterSuccesseur ajoute aussi dans autre.predecesseurs.
3Graphes pondérés ?
On ne peut plus stocker directement un Sommet : la liste contient des objets Arc(destination, poids), ou le sommet utilise une Map<Sommet, Double> (successeur → poids).
4Graphe non orienté : où est mémorisée l'arête {A,B} ?
Deux fois : B dans la liste de A et A dans la liste de B. Inconvénients : redondance de mémoire, risque d'incohérence (oublier l'une des deux copies), les arêtes sont comptées deux fois en parcourant tous les sommets, une information portée par l'arête serait dupliquée (ou partagée via un objet Arc commun).
5Multigraphes ?
Utiliser une liste (avec doublons autorisés) plutôt qu'un ensemble, ce qui permet de compter m(u,v) ; ou une Map<Sommet,Integer> successeur → multiplicité ; ou, si chaque lien porte une information, une liste d'objets Arc.

Questions sur le graphe complet Kn Chap. 3
1Degrés des sommets dans Kn ?
Chaque sommet est adjacent aux n−1 autres : tous les sommets ont pour degré n−1 (le maximum possible dans un graphe simple d'ordre n).
2Nombre d'arêtes de Kn ?
Somme des degrés = n(n−1) = 2m, donc m = n(n−1)/2. Autre façon : on choisit 2 sommets parmi n, soit C(n,2). Vérification : K2 : 1, K3 : 3, K4 : 6, K5 : 10 (confirmé par un programme de comptage).

Étape 1 : modélisation

Sommets = les 8 produits p1…p8. Arête {pi, pj} ⇔ pi et pj sont incompatibles, donc ne peuvent pas être stockés dans la même zone. Les 8 arêtes : p1p4, p2p3, p3p4, p3p5, p3p8, p4p7, p5p6, p7p8 (chaque incompatibilité est symétrique). Étape 3 : peut-on améliorer l'algorithme ?

  • Ordre de la question B : degrés décroissants. Degrés : p3=4, p4=3, p5=p7=p8=2, p1=p2=p6=1.
  • Pourquoi c'est judicieux : les sommets très connectés ont le plus de contraintes ; en les traitant en premier, on les place quand il reste le plus de choix. Les sommets de petit degré (peu de voisins) se casent facilement à la fin.
  • Stratégie encore plus pertinente : DSATUR — à chaque étape on colorie le sommet dont les voisins portent le plus de couleurs différentes (égalité : plus grand degré). Sur ce graphe, DSATUR trouve aussi 2 zones.

2. Est-il possible de faire les examens sur 3 créneaux ?

5. Quels examens sont les plus difficiles à planifier ?

DSATUR : à chaque étape, on prend le sommet de plus grand degré de saturation (nombre de couleurs différentes déjà présentes chez ses voisins), en cas d'égalité le plus grand degré, avec la plus petite couleur possible ; l'ordre s'adapte à la coloration en cours.
