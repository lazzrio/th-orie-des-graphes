Pourquoi le BFS ne suffit plusLa première découverte d'un sommet n'est plus forcément par le chemin de plus petit poids (A→D : le BFS donne 15, le PCC vaut 13). Il faut mémoriser une distance provisoire par sommet et la mettre à jour. Brute force (tous les chemins) : exponentiel.

Algorithme de Dijkstra

  1. Initialisation : dp(s₀) = 0, dp(s) = ∞ ; aucun sommet marqué ; pas de parents.
  2. Répéter : choisir et marquer le sommet non marqué de plus petite dp (smin) ; pour chaque successeur non marqué s : si dp(smin) + p(smin, s) < dp(s), alors dp(s) ← cette valeur et Parent(s) ← smin.
  3. Arrêt : plus de sommet non marqué à distance finie (ou, pour un PCC vers t seulement : dès que t est marqué).
  • Distance d'un sommet marqué = définitive (preuve par l'absurde : un chemin plus court passerait par un non marqué de dp ≤).
  • Poids ≥ 0 indispensables (sinon Bellman-Ford ou Floyd-Warshall). Si tous les poids valent 1, Dijkstra = BFS.
  • Sortie : une arborescence de PCC enracinée en s₀ ; chemin = remonter les parents. Un seul critère optimisé.

  • File de priorité : sort l'élément de plus haute priorité (pas le plus ancien) ; PriorityQueue : add, peek (sans retirer), poll (retire, null si vide), remove, contains, size ; ordre fourni par Comparable (compareTo) ou Comparator (compare).
  • Parcours des successeurs : O(n²) (matrice) ou O(m) (listes) sur l'ensemble des étapes.

Limites et perspectives

  • Poids négatifs → Bellman-Ford, Floyd-Warshall. Très grands graphes → prétraitement, Contraction Hierarchies, ALT ; destination connue → A*. Plusieurs critères → algorithmes multicritères, front de Pareto.

  • BFS/DFS mélangés (même ligne en tête de file) : plus FIFO, plus de garantie (Tolbiac → Gare de l'Est : 17 tronçons au lieu de 12).
  • Ordre préférentiel (même ligne d'abord, puis fin de file) : reste un BFS, avantage local seulement (contre-exemple A→F : A-B-C-F avec 2 changements alors que A-B-G-F en a 1).
  • Comparer globalement : paire (tronçons, changements) comparée dans cet ordre ; remplacer le chemin mémorisé si même nombre de tronçons et moins de changements ; première découverte insuffisante → idée de coût et de Dijkstra.
Pièges classiques
  • Longueur (nombre d'arcs) ≠ longueur pondérée (somme des poids) ; PCC ≠ chemin avec le moins d'arcs.
  • Dijkstra : on arrête à t marqué, pas à t découvert ; on ne met à jour que les successeurs non marqués.
  • Poids négatifs : Dijkstra donne un résultat faux (la preuve suppose poids ≥ 0).
  • HashMap : ordre d'itération ≠ ordre d'insertion ; get renvoie null (pas d'exception) si la clé manque.
  • peek() consulte, poll() retire.
