Rappels des semaines 1 et 2 utiles ici

  • Succ(x) : successeurs de x (arcs sortants) ; Pred(x) : prédécesseurs (arcs entrants) ; Adj(x) : voisins en non orienté. Ordre n = nombre de sommets, taille m = nombre d'arêtes (d'arcs).
  • Matrice d'adjacence (sommets numérotés de 0 à n − 1) : mij = 1 si j est un successeur de i. Ligne i = successeurs de i, colonne j = prédécesseurs de j ; symétrique en non orienté.
  • Liste de successeurs : chaque sommet connaît ses successeurs (getSuccesseurs() dans l'activité 8) ; mémoire en n + m. C'est elle qui donne les parcours en O(n + m).

Explorer depuis un sommet initial

  • Découvrir = rencontrer pour la première fois ; explorer = parcourir ses successeurs. États : 0 non découvert, 1 découvert, 2 exploré.
  • Marquer un sommet dès sa découverte (quand il entre dans la collection), sinon il peut y entrer plusieurs fois.
  • On découvre exactement les sommets atteignables depuis le départ, quelle que soit la stratégie ; seul l'ordre change. Donc : v est atteignable depuis s ⇔ v est découvert par une exploration depuis s.
  • Sauf indication contraire, on parcourt les successeurs dans l'ordre alphabétique (ou croissant) : il faut le respecter, car il fixe l'ordre obtenu.
BFS (file) ou DFS itératif (pile)
marquer s0 ; ajouter s0 à la collection
tant que la collection n'est pas vide :
    retirer s   (file : le plus ancien ; pile : le dernier ajouté)
    pour chaque successeur t de s :
        si t n'est pas marqué :
            marquer t ; ajouter t à la collection
DFS récursif
explorer(s) :
    pour chaque successeur t de s :
        si t n'est pas marqué :
            marquer t ; explorer(t)

Méthode pour dérouler un parcours (exercice type)
  1. Écrire la liste des successeurs de chaque sommet, dans l'ordre imposé.
  2. Tableau : étape | sommet retiré | nouveaux découverts | collection (file : tête à gauche ; pile : sommet à droite).
  3. Marquer et ajouter un successeur seulement s'il n'est pas déjà marqué ; un sommet entre une seule fois dans la collection.
  4. Ne pas oublier les sommets non atteignables (ex. 7 : F reste à l'état 0) ; s'arrêter quand la collection est vide.
  5. Si on demande les parents : noter parent[x] = y au moment où x est marqué.

Chemins et arborescence de parcours

  • À la découverte de x depuis y : parent[x] ← y (la racine n'a pas de parent, un sommet non découvert non plus).
  • Les arcs parent → enfant forment une arborescence de parcours enracinée au départ.
  • Chemin départ → x : remonter les parents depuis x jusqu'à la racine, puis inverser. Si on n'atteint jamais la racine, x n'est pas atteignable (liste vide).
  • BFS et DFS donnent des arborescences, donc des chemins, en général différents. Exercice 7 vers A : C → B → A (2 arcs) avec la file ; C → H → J → I → A (4 arcs) avec la pile.
  • Le tableau des parents ne sert que pour les chemins qui partent de sa racine : pour un autre départ, il faut relancer un parcours.
  • Le BFS minimise le nombre d'arcs, pas une somme de poids : pour des arcs pondérés, il faudra Dijkstra (semaine 4).

Faible connexité

  • Connectés = reliés par une chaîne (on ignore l'orientation). C'est une relation d'équivalence.
  • Composantes connexes = classes d'équivalence = sous-graphes connexes maximaux ; elles forment une partition. CC(s) = composante de s. Un sommet isolé forme une composante à lui seul.
  • Non orienté : une exploration depuis s découvre exactement CC(s). Connexe ⇔ une exploration découvre tous les sommets.
  • Toutes les composantes : relancer une exploration depuis chaque sommet non encore marqué (marques partagées) ; une exploration par composante (3 composantes ⇒ 3 explorations).
  • Graphe orienté : explorer avec successeurs et prédécesseurs pour la faible connexité. Faiblement connexe n'implique pas « tout est atteignable depuis un sommet » (exercice 7 : faiblement connexe, mais F inatteignable depuis C).
  • Comptage : un graphe connexe d'ordre n a au moins n − 1 arêtes ; un graphe acyclique en a au plus n − 1 ; connexe et acyclique ⇒ exactement n − 1 (c'est un arbre).
